# Project structure

A LaTeX document that grows over a semester needs a layout where every piece has an
obvious place. This structure has worked well:

```
<doc>/
├── main.tex                     # master: document class, packages, \input{preamble/preamble}, \input sections
├── AGENTS.md  + CLAUDE.md       # writing rules for agents (CLAUDE.md -> AGENTS.md symlink)
├── preamble/
│   └── preamble.tex             # shared boxes, colours, macros, plot styles, toggles
└── sections/
    └── <topic>/                 # one folder per main section (\section)
        ├── AGENTS.md + CLAUDE.md  # optional, section-specific rules (add to the general ones)
        ├── <topic>.tex          # entry point: \section{...}, \label{sec:<topic>}, short intro, \input of sub-sections
        └── <sub-topic>/         # one folder per sub-section (\subsection)
            ├── <sub-topic>.tex  # \subsection{...} + \label{sec:<sub-topic>}
            └── assets/          # figures generated by scripts + the scripts themselves
```

## Rules and why

- **Entry point named like its folder** (`sections/math-recap/math-recap.tex`). You can
  always find the file to open without guessing.
- **kebab-case** for folders and files: no spaces, no case surprises across OSes.
- **One folder per (sub-)section**, so assets live next to the text that uses them and a
  section can be moved or deleted as a unit.
- **Paths are relative to the folder of `main.tex`** (where latexmk runs):
  `\input{sections/topic/sub/sub}`, `\includegraphics{sections/topic/sub/assets/fig.pdf}`.
  Write them out in full; do not rely on `\graphicspath` tricks that hide where files are.
- **One preamble for the whole document**, loaded once from `main.tex`. Sections never
  define their own packages or macros; if a section needs a new macro, add it to the
  preamble (checking it does not clash with an existing name).
- **Labels**: `\label{sec:<folder-name>}` right after each `\section`/`\subsection`. They
  must be unique across the whole document, which is automatic if they follow the
  folder names. Reference earlier material with `\ref` instead of re-explaining it.
- **Adding a section** = create the folder + entry file, then add exactly one
  `\input{sections/<topic>/<topic>}` line to `main.tex` (or to the parent entry file
  for a sub-section).
- **Agent rules live with the content**: a general `AGENTS.md` at the document root,
  more specific ones inside section folders. Symlink `CLAUDE.md -> AGENTS.md` (relative
  link: `ln -s AGENTS.md CLAUDE.md`) so every agent reads the same file. Keep the general
  file free of section-specific details; put those in the section's own `AGENTS.md`.

## Writing placeholders while building

When a section is referenced (`\ref{sec:x}`) before it exists, create the entry file with
just its `\subsection{...}` and `\label{...}` so the document compiles. Replace it when
you write the real content.

## Restructuring

1. In a git repo, check the tree is clean, then `git mv` so history follows the files.
2. Rename identifiers with **whole-word** matching only (a naive replace of `mrule` would
   break `\bottomrule`). Prefer an explicit list of names over a broad regex.
3. Update every `\input`, `\includegraphics`, `\inputminted` path and every path
   mentioned in `AGENTS.md` files.
4. Rebuild from clean: `latexmk -C main.tex && rm -rf _minted*`, then compile.
5. Grep the PDF text (`pdftotext main.pdf - | grep ...`) for old names or paths.
